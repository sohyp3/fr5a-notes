# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

fr5a is a Bear-style Markdown editor for Linux: **Electron + Svelte 5 + TipTap**, bundled by **electron-vite**, packaged with **Bun**. The filesystem (a user-chosen folder of `.md` files) is the source of truth; SQLite is a disposable index.

## Commands

- `bun install` — deps; `postinstall` rebuilds `better-sqlite3` for Electron's ABI.
- `bun run dev` — electron-vite dev with HMR (launches the app).
- `bun run build` — bundle main/preload/renderer into `out/`.
- `bun run check` — `svelte-check` type check (the real type gate; the build uses esbuild and does **not** type-check).
- `bun run lint` — `prettier --check` + `eslint`. `bun run format` to fix.
- `bun run test` — vitest (`--run`). `bun run test:watch` for watch mode.
- Single test: `bunx vitest run src/main/tags.test.ts` (or `-t "<name>"` to filter by test name).
- `bun run rebuild` — re-run the native `better-sqlite3` build after an Electron upgrade or ABI error.
- `bun run dist` — package a Linux AppImage + `.deb` via electron-builder.
- `bun run test:e2e` — Playwright mobile-layout tests (`e2e/`, phone 390×844 + tablet 800×1280, fake `window.api`).
- Version: bump `version` in `package.json` only. `build-info.ts` injects `__APP_VERSION__` + `__APP_COMMIT__` (short sha, `+` if dirty) into the renderer (shown under Settings' section list); Android's `versionName`/`versionCode` (`android/app/build.gradle`) read it too.
- `bun run apk` — Android: web bundle (`vite.android.config.ts` → `out/android`), `cap sync android`, `gradlew assembleDebug` → `android/app/build/outputs/apk/debug/app-debug.apk`. Gradle needs JDK 21 (`android/gradle/gradle-daemon-jvm.properties` picks it).

## Platform layer (desktop + Android)

The renderer never touches `window.api`; it imports `platform` from `lib/platform` (a `PlatformApi`, `platform/types.ts`), chosen at startup: `desktop.ts` wraps the Electron preload, `api.android.ts` is the Capacitor host. Android keeps notes in `notes/` under app-private storage (Filesystem `Directory.Data`, no SAF / storage permissions), state in Preferences, and an in-memory index rebuilt on launch, resume and after each sync. Android git (`platform/git/isoGit.ts`) is isomorphic-git over a Capacitor fs adapter (`capFs.ts`) and native HTTP (`capHttp.ts`, buffered base64 bodies — no CORS proxy); same contract as `main/gitSync.ts` (commit-then-merge, never force-push; a push first folds the app's own unpushed commits into one on top of the remote — `squashUnpushed`, a soft reset — so only the notes as they are at push time leave the device, never an earlier state such as a note before it was encrypted; desktop keeps hand-made commits as they are). A pull never changes a note's mtime (the list order): both back ends stat the files the merge may rewrite and set those times back after it — conflicted files as each is resolved, everything on abort (the times are kept in the git dir while a merge is stopped) — and a file new to the device, a fresh clone included, gets the author time of its last commit. Android sets times through the app-local `FileTimes` plugin (`android/…/FileTimesPlugin.java`, registered in `MainActivity`, called as `capFs` `utimes`), since Capacitor's Filesystem can't. The GitHub token lives only in Keystore-backed secure storage. `isoGit.test.ts` runs it in Node against a bare repo via `git http-backend` as CGI. Conflicts reuse `ConflictWindow.svelte` as an in-app overlay (`conflictsInline`). The oldest target WebView is Chromium 92 (a Huawei tablet): `vite.android.config.ts` lowers syntax to `chrome92` and injects usage-based core-js polyfills (`@vitejs/plugin-legacy`, modern chunk only); avoid CSS newer than that (no `color-mix()` — `accents.ts` mixes colors in JS). It also sizes an absolutely positioned `<button>` to its content even with `inset: 0`, so scrim buttons get an explicit size (`button.scrim` in app.css).

Layout (`lib/layout.ts` `layoutFor`, store `layout`/`touch`): mouse windows are always `desktop`. Touch devices (Android or coarse pointer): `phone` <600px stacks nav → list → editor → harness (`pane`, `back()`, top-bar Back); `tablet` 600–1023px shows list + editor with folders in a drawer (`drawerOpen`); ≥1024px is the three-pane layout. `App.svelte` keeps every pane mounted and switches layouts with CSS only, so rotation keeps the TipTap instance and caret — don't reintroduce per-layout `{#if}` branches around `<Editor />`. Settings and Changes (`view`) are overlays over the still-mounted list + editor, for the same reason. Phone panes slide: each wrapper gets `data-pos` before/current/after and hidden ones are `visibility: hidden` after the transition. Desktop/tablet: the note list toggles (`listOpen`, Mod+Shift+L, also on landscape tablets) and pane edges drag to resize (`Resizer.svelte`, `widths`, persisted in the `sidebar` state's `panes`). With the AI pane open on a narrow window (a 1024px landscape tablet) `fit` narrows the panes; `--harness-w` is the fitted width, not the stored one, or the pane's content is cut off. The tablet AI pane is a scrim-backed bottom sheet with a drag handle (`sheetExpanded`); it and the folders drawer are one-at-a-time overlays (opening either closes the other), and the sidebar fills the drawer's width. `html[data-touch]` enlarges targets (44px); `FormatToolbar.svelte` shows on touch layouts while editing. Vim is off on Android; ghost syntax has no hover reveal when `html[data-hover=none]`. Phones use bottom sheets (`ActionMenu.svelte` `sheet`) for the note menu and overflow menus; menus and sheets are portaled to `<body>` (`lib/portal.ts`) because the sliding panes are transformed. Motion uses the `--dur-fast/--dur-pane/--dur-sheet` + `--ease-out` tokens (app.css), zeroed under `prefers-reduced-motion`; JS transitions multiply by `reducedMotion() ? 0 : 1`.

Touch gotchas (each caused a real bug): `.body` (its `.layout-phone` rule too) is `overflow: clip`, not `hidden` — off-screen drawers/sheets otherwise make it scrollable and focus/scrollIntoView shifts the whole UI. Note cards swipe with pointer events (`touch-action: pan-y`, direction lock) and reveal one action that commits on a clean `pointerup`, not `click` — Chrome drops the click of a tap made right after a swipe/fling. Anything that opens under the finger on pointerup gets that tap's click: `ConfirmDialog`'s scrim only cancels for a press that started on it.

View / edit mode: `app.editing` (setting `openIn`: `auto` = view on touch, edit with a mouse; new notes always edit). Toggled with `editor.setEditable()` — no remount — via the editor header's Edit/Done, double-tap, or Mod+Shift+E. In view mode the editor never autofocuses, so the Android keyboard stays down. The editor header (`.editor-head`) is a strip in normal flow above the scroll area, not an overlay.

## Native module gotcha

`better-sqlite3` is compiled for Node's ABI by `bun install`, but runs under Electron's ABI. If you see "Could not locate the bindings file" or a `NODE_MODULE_VERSION` mismatch at runtime, run `bun run rebuild`.

## Three-process architecture (electron-vite)

- `src/main/` — Node main process. `index.ts` owns the frameless window, IPC handlers, workspace lifecycle, and persistence: `electron-store` (`userData/fr5a.json` — workspace, last open file, sidebar layout, settings; renderer reads/writes it via the `state:get`/`state:set` channels with a key whitelist) plus the SQLite index (`userData/fr5a-index.db`). `fileService.ts` is the "Local File Service" (recursive scan, chokidar watch, read/write/create/delete). `db.ts` is the SQLite index. `tags.ts` parses/nests tags.
- `src/preload/index.ts` — the **only** bridge to Node. `contextIsolation` is on; the renderer touches the filesystem exclusively through the typed `window.api` (`contextBridge`). `index.d.ts` augments `Window`.
- `src/renderer/` — plain Vite + Svelte 5 (no SvelteKit). Mounted in `src/renderer/src/main.ts`.
- `src/shared/types.ts` — types + the `Channels` map of IPC channel names, shared across all three processes so they can't drift.

Data flow: main scans the folder → indexes into SQLite → renderer pulls `listNotes`/`listTags` over IPC. chokidar changes re-index and push a `notesChanged` event that triggers a renderer `refresh()`.

Move / rename: `platform.moveNote(id, to)` (keeps the extension, numeric suffix when taken) and `moveFolder(path, to)` (refused when the target exists, lies inside the folder, or the folder holds a nested git repo — its sync setup is tied to the path); rules shared in `shared/paths.ts`. The store's `renameNote`/`moveNoteTo`/`renameFolder`/`moveFolderTo` flush first, make saves queued mid-move wait (`moving`) and then `pathMoved` re-points the open note (no editor remount — the key is the session), filters, folder expansion and `onMoved` listeners (harness attachments, saved-chat links); a folder's AI privacy moves with it (`folderMoved`), and moving out of a hidden folder asks first. `platform.deleteFolder(path)` soft-deletes a folder: every file in it moves to `.fr5a_trash` at its mirrored path (notes restorable one by one), refused for the root, hidden folders, a nested repo or a locked note; the store's `deleteFolder` asks first and forgets the folder's expansion / hidden state. Hidden folders (`settings.hiddenFolders`, per device; not "hidden from cloud AI"): kept out of the sidebar tree (`listedNotes` / `listedFolders`), All Notes, tags and search unless browsed into from Settings → General (`openHiddenFolder`); Settings → AI has a checkbox for the saved-chats folder. UI: note/folder menus (`NoteContextMenu`, `FolderContextMenu` — right-click, long-press, hover ⋯), the editor crumb, `MoveDialog` (folder picker; typing a new path creates it), `PromptDialog` (`app.prompt`), mouse drag-and-drop onto folders / All Notes (`lib/dnd.ts`). `app.notify` shows a short `Notice`.

## electron.vite.config.ts — external deps (critical)

`main` and `preload` use an explicit `external` predicate (NOT `externalizeDepsPlugin`, which silently externalized nothing here). `electron`, node builtins, `better-sqlite3`, `chokidar`, and `electron-store` MUST stay external so they resolve from `node_modules` at runtime — bundling them breaks the native binding and pulls in electron's launcher wrapper. If you add a native or Node-only runtime dependency used by main/preload, add it to `runtimeExternals`.

## The editor model — raw Markdown text (most important concept)

The TipTap document is **literally the Markdown file, one paragraph per line** (`markdown.ts` `textToDoc`/`docToText`). There are no semantic heading/bold/list nodes. `#`, `**`, `>`, `-` stay as text; `MarkdownSyntax.ts` (a ProseMirror plugin) paints decorations over the syntax instead of transforming it. Consequences:

- Saving is just `docToText` → newline-join; the buffer _is_ the file.
- "Bold" (`MarkdownShortcuts.ts`) wraps the selection in literal `**…**`; there are no marks.
- List behavior (`ListBehavior.ts`) manipulates the raw text (Tab = 2-space indent, Enter continues the bullet/number, double-Enter clears) rather than sink/lift list nodes.
- **Ghost Syntax**: `.md-syntax` is hidden with `font-size:0` (not `display:none`, to avoid layout jumps) and fades in on line-hover / when the caret enters the token (`md-active`, computed from the selection). Bullet markers are the deliberate exception — never hidden (`.md-bullet-mark`).
- `vim.ts` is a from-scratch ProseMirror Vim plugin (no maintained package exists): modes/motions/operators, block cursor, mode badge. Loaded only when `settings.vim` is on.

The Editor component mounts TipTap via a Svelte **attachment** (`{@attach mount}`) inside a `{#key}` on `` `${editorSession}:${vim}:${highlights}:${editorReloadToken}` `` so opening a note / toggling vim or highlights / external rewrites recreate the instance. `mount` builds the editor inside `untrack` — an attachment re-runs when state it reads changes, and only the key may recreate the editor; view ⇄ edit is a second attachment (`followEditable`) calling `setEditable`. Three subtleties that caused past bugs: (1) the store loads note content **before** bumping `editorSession` (the editor reads content at mount time); (2) the mount attachment's teardown destroys only its _own_ editor instance (`if (editor === ed)`), since a keyed swap may have already reassigned the shared `editor` ref; (3) the key is the session counter — NOT `activeId` — because a **draft note** (created in-memory with an empty `# ` H1, no file yet) gains its `activeId` on first save (the typed H1 becomes the filename, see `materializeDraft`), and that must not remount the editor mid-typing.

Tables (`tables.ts`, painted by `MarkdownSyntax.ts`, edited by `TableBehavior.ts`): a GFM pipe table shows as a rendered `<table>` widget (`tableHtml`, cells through `renderInline`, so escaped) with its lines `display:none` — until the caret is inside it while editable, when the lines show as a mono source block. A press on a cell puts the caret in that cell's source (`data-line`/`data-cell` → `cellRanges`); arrows beside a rendered table step into it; Tab/⇧Tab select the next/previous cell; Enter at a row's end adds a row, on an empty row leaves the table. Pasting tab-separated text (spreadsheets, web tables) inserts a padded Markdown table (`parsePastedTable`/`toMarkdownTable`); Mod+Shift+V pastes raw. The plugin mirrors `view.editable` into its state (a meta transaction), since view mode always renders. Don't lay table rows out as CSS tables: anonymous table boxes break Chromium hit-testing and caret movement.

Images (`images.ts`, widget + resize in `imageView.ts`, keys / paste / drop in `ImageBehavior.ts`): a line holding only `![alt](src)` shows its picture _above_ the line; the line and an optional `<!-- size: N% -->` comment right below it (width as a share of the text column) are `display:none` until the caret enters them, then show as source under the picture (arrows step in, Backspace / Delete beside a hidden block move into it rather than join, Enter on the image line opens a line below the size comment). The corner handle drags the size (double-click: original size). Dragging the picture (touch: long-press ~400ms first, a plain swipe scrolls) moves the image line and its size comment to another gap (`moveImage`): `dropGaps` keeps it out of fenced code, tables, image / highlight pairs and the leading metadata comments; `moveLines` takes a doubled blank line along and pads next to a table; one undo step, Escape cancels. A non-passive `touchmove` on the widget stops the scroll once lifted. `src` resolves from the note's folder (`/x.png` = workspace root; https and `data:image` as is; other schemes refused). Pasted / dropped / Insert → Image… files go through `app.saveImage` → `platform.saveAsset` into `assets/` at the workspace root, linked relative to the note (images aren't encrypted, and moving a note doesn't rewrite its links). `<img>` loads via `platform.assetUrl`: desktop the `fr5a://workspace/<path>` protocol (`main/index.ts`, images inside the workspace only — `fileService.assetPath`), Android `Capacitor.convertFileSrc`; the CSP's `img-src` allows `fr5a:` and `https:`. A new block inserted with the caret in a table / image block goes after it (`outsideBlocks`).

Dividers: `---` / `***` / `___` (spaces allowed) draw a hairline / three dots / a double rule — the line's `::after` beside the ghosted syntax (`md-hr-line|dots|double`).

Highlights (`highlights.ts`, `HighlightBehavior.ts`; setting `highlights`, Settings → Editor, on by default — off: no plugin, no button, no shortcut row, and the comments are plain text): `<!-- highlight -->` marks the whole line next to it (block prefix excluded), `<!-- highlight: 4-12, 20-25 -->` stretches as `text.slice` offsets. The comment marks the line below; below the line works only when no text follows it (a comment between two text lines marks the lower one), so the editor always writes it above. Mod+Shift+H / the toolbar's Highlight / Insert menu toggle the selection (no selection: the line); `appendTransaction` maps ranged offsets through edits to the marked line (not when the comment itself was edited), and Backspace / Delete across a hidden comment join the text lines with the highlight moved along. Comment lines are `display:none` unless the caret is on one or Ghost Syntax is off. Title / snippet derivation skips comment lines (both hosts + `noteSnippet`).

Insert menu: the editor header's `+` (mouse, edit mode) and the touch toolbar's `+` offer Image… / Table… (`TablePicker.svelte`: a size grid — popover, or a phone sheet where a tap sizes and Insert confirms — then `insertTable` puts a blank padded table at the caret, caret in the first header cell).

Tag autocomplete (`TagSuggest.ts`): a `@tiptap/suggestion` plugin on `#` showing a floating dropdown (plain DOM, `.tag-suggest` in app.css) of tags from the index; Tab/Enter completes. It has `priority: 1000` so its Tab handling beats `ListBehavior`'s Tab-indent while open.

## AI harness (`lib/harness/`, `components/harness/`)

On-device agent loop over OpenAI-compatible providers; only the HTTP request leaves the device. The renderer CSP blocks `fetch`, so network goes through `platform.httpFetch`/`httpStream` (desktop: `main/http.ts` via `net.fetch`, streamed over `http:chunk`; Android: buffered `CapacitorHttp`, the SSE body is parsed whole). Pure, Node-tested modules: `openai.ts` (client + delta accumulator), `sse.ts`, `loop.ts` (model → tools → model, `maxSteps`), `tools.ts` (read/list/search notes, `ask_user`, `write_note`, `web_search`, `fetch_url`), `context.ts` (system prompt, token budget), `privacy.ts`, `session.ts`, `skills.ts`, `web.ts`, `diff.ts`, `edits.ts`. Runtime: `harness.svelte.ts` (tabs, streaming batched per rAF, question/approval promises) and `apply.ts` (writes to the open note go through `app.editor.commands.setContent` so undo + auto-save apply). `write_note` never writes without the diff card's Apply.

- Config (`ai` state key, `config.svelte.ts`) holds provider profiles, search provider (DuckDuckGo needs no key; SearXNG / Brave / Tavily), local-only folders; API keys go to `platform.getSecret/setSecret` (desktop `safeStorage`, Android Keystore) — never into state or notes. Search keys are per provider (`search:<kind>`, legacy `search` read as fallback); Settings saves a typed key on Enter / blur / Test. `ai.keys` says which providers have a key here; the pane's model picker offers only `ai.usable` ones (local or keyed).
- Transcript: AI replies render through `render.ts` (`renderReply`: escapes every character, emits only its own tags, http(s)/mailto links; a bare JSON reply becomes a highlighted block) — only `render.ts` output (`renderReply`, `highlightJson`) may go through `{@html}`. Mentions (`mentions.ts`): `@note`, `@Folder/` (or pick from `@/`), `@#tag`, and `@tabs` = every note open in a tab when sent (`@"tabs"` is a note called tabs); the "open note" chip reads "current tab" while tabs are on. `ask_user` takes up to 4 questions per call (`questions.ts`, shown as one stepped `QuestionPanel`); `write_note` keeps its reviewed diff on the tool row. `errors.ts` classifies failures (`content` = a provider's moderation refusal). A run that breaks off (error, Stop) keeps what finished: `retry()` carries on from `resumeAt` (`loop.ts` `pendingCalls` re-runs the step's unfinished calls, so a pending question / diff comes back; after a content refusal the last tool results are withheld), and a new message first closes open calls (`closeCalls`); after a finished reply `retry()` rewinds to the `you` entry's `mark` and resends. Stop is immediate: the loop races each request and tool against the abort (`abortable`), since Android's buffered HTTP and the web tools can't be cancelled. The question / approval cards shrink with the pane (keyboard up, short sheet) and only their body scrolls.
- Save / fork (session ⋯ menu): `saveToNotes` writes the chat as a readable note (`sessionToNote`) into the `chatsFolder` setting (default `AI chats/`), so it syncs with the notes; the session's frontmatter keeps `saved` + `savedHash`, so saving again updates that note and asks before replacing edits made since. A local-provider chat that touched hidden notes gets `<!-- ai: local -->`. `fork` copies the tab (entries, exact model history) into a new session file; the original stays as it was.
- Privacy wording: notes are "hidden from cloud AI" (folder in `localOnlyFolders`, or the note's `<!-- ai: local -->`, indexed as `NoteMeta.aiLocal`); providers that "run on my hardware" (`local`) may read them. `privacy.ts` `folderPrivacy` says whether a folder is hidden itself or via a parent; the sidebar, note cards, editor header, move picker and Settings → AI tree all show it. `config.svelte.ts` is cheap to import app-wide (the OpenAI client loads on demand).
- Cost (`usage.ts`): requests ask for `stream_options.include_usage` (dropped per endpoint if refused) and OpenRouter's `usage.include`; each run's tokens become a `UsageRecord` in the session frontmatter (`usage: [at|provider|model|in|out|cost]`). Cost = provider-reported, else the profile's `price` (USD per 1M in/out tokens, Settings → AI), else models.dev's price for the model (`prices.ts`: matched by base URL, only the configured endpoints kept in the `aiPrices` state key, refetched after 3 days), else 0 for local, else unknown (priced later once a price is known). Lookups go through `ai.priced(provider, model)`. Each reply shows its run's line, the context bar the chat total, and `UsagePanel` (session ⋯ → Usage & cost, Settings → AI → Usage) adds every session up: today / month / all time, per model, per chat.
- Sessions (`.fr5a/sessions/*.md`, `<!-- turn: … -->` separators; a chat that read an encrypted note is saved in `sessions/device/`, kept out of git by `sessions/.gitignore`, until ⋯ → Sync this chat — see `HarnessTab.keepOnDevice`, list keys `device/<file>`) and skills (`.fr5a/skills/*.md`, frontmatter + prompt; built-ins seeded into an empty folder) are read/written via `platform.readMeta/writeMeta/listMeta` (paths relative to `.fr5a/`, can't escape it). Dot-folders aren't indexed as notes.
- The pane is lazy-loaded (`app.harnessLoaded`) and then always mounted: desktop side split (Mod+J), tablet bottom sheet, phone `pane='harness'`.

## Multi-repo sync

`shared/multiSync.ts` runs pull/push over the root repo plus nested repos (folders with their own `.git`, e.g. `private/`, `.fr5a/`), stops at the first conflict (paths prefixed with the repo folder), and routes resolve/abort to the repo mid-merge. Nested folders are added to the root `.gitignore` (`withNestedIgnored`) before any commit, so their files never reach the root remote. Desktop discovers nested repos on disk (`main/repos.ts`); Android keeps a list + per-repo token (`syncAddRepo`). `syncAddRepo` clones into a new/empty folder or turns a folder that has notes into a repo in place (first pull merges unrelated histories), and the parent repo untracks the folder (`git rm --cached` / isoGit `untrack`) — `.gitignore` alone doesn't stop tracked files from being committed. Desktop copies the notes repo's local `credential.*`/`user.*` config into the new repo (a repo-local `credential.helper store` is otherwise invisible to it). `repoOf`/`byRepo` route workspace paths to their repo.

## Changes (git status + diff)

`platform.gitChanges()` returns notes that differ from the last commit with their committed text (`GitChange`), root + nested repos, `.md/.markdown/.txt` outside dot-folders only (`isTrackedNote`). Desktop: `main/gitChanges.ts` (read-only `git status --porcelain -z` + `git show HEAD:`); Android: `isoGit.ts` `changes()` (statusMatrix). The store refreshes it (debounced) after file changes and syncs; `Changes.svelte` lists files with `DiffView.svelte` diffs (shared with the AI approval card). Without git it shows the open note's diff since it was opened (`baseline`).

Stash / revert (`gitStash`, `gitStashes`, `gitStashApply`, `gitStashDrop`, `gitRevert`; share the sync lock): desktop `main/gitStash.ts` uses real `git stash push -u -- <notes>` (terminal stashes show up too; stashes are addressed by commit sha, not index); Android keeps JSON snapshots in each repo's `.git/fr5a-stash/` (isomorphic-git's stash skips untracked files). Apply refuses when a stashed note has edits since; desktop may report merge conflicts (markers left, stash kept). Revert restores HEAD; notes HEAD lacks go to the trash. The store's `gitOp` flushes the auto-save first and `reloadFromDisk`s after.

## Per-file metadata (hidden HTML comments)

Direction and pinning live in comment lines at the top of the file: `<!-- dir: rtl -->` and `<!-- pinned: true -->` (also `<!-- locked: true -->`, and `<!-- ai: local -->` = only local AI providers may read the note, see `harness/privacy.ts`). They are parsed in both `main/fileService.ts` (stripped from title/snippet; `pinned`, `locked` and `aiLocal` indexed — SQLite columns in `db.ts`, and Android's `buildMeta`) and renderer `markdown.ts` (`detectDir`/`setDir`/`detectPinned`/`setPinned`), and hidden in the editor via the `md-meta` node class in `MarkdownSyntax.ts`. When adding a new metadata key, update all three places.

## Encryption (`lib/vault/`, `shared/encrypted.ts`)

Opt-in (`settings.encryption`, off by default). Off means no cost: OpenPGP (~250 KB), `vault.svelte.ts` and `EncryptionSettings.svelte` are lazy chunks, no wrapper on `platform`, no key, no timers, no buttons (the shortcut row is `feature`-gated) — keep it that way. An encrypted note is the same `.md` file: its leading metadata comments stay in the clear (pin / lock / AI indexing and the delete-lock check keep working), the rest is one armored OpenPGP message (`gpg -d` reads it). The indexers only see ciphertext: `NoteMeta.encrypted`, title = file name, no snippet or tags.

- One curve25519 keypair for every device, generated or pasted in Settings → Encryption and stored armored, still passphrase-protected, via `setSecret('pgp:key')` (desktop `safeStorage`, Android Keystore) — never in state, notes or git. Unlocking decrypts the private key once (`app.prompt({ secret, submit })`); it lives only in `Vault`'s `#private` field. "Remember passphrase" (Settings → Encryption) keeps the passphrase as `pgp:passphrase` in secure storage: the vault unlocks with it at start and whenever a locked note is needed (`unlockSaved`), and switching it off (or removing the key) deletes it. Lock (title-bar button, Mod+Shift+K, `autoLockMinutes` idle / in the background, quit, switching off) flushes, closes an open encrypted note (new editor session, so its undo history goes too) and drops the decrypted titles.
- `platform` is a copy of `hostPlatform`; while on, `wrap.ts` methods are swapped in and the host's put back when off. `readNote` decrypts (`VaultLockedError` while locked); `writeNote` re-encrypts when the file on disk is encrypted (public key only: works locked and never writes plain text over ciphertext; skips no-op writes, since ciphertext always differs); `listNotes` / `listTags` overlay real titles and tags (cached by id + mtime); `gitChanges` / `gitStashes` / `syncConflicts` decrypt while unlocked. Sync, stash, move and trash only ever move ciphertext. "Remove encryption" writes through `hostPlatform`; pin / lock / AI-marker edits on a note that can't be read edit the raw file (`readForMeta`). New drafts can be marked encrypted before their first save (`draftEncrypted`). Folders: "Encrypt all notes" / "Remove encryption from all" convert every note below a folder (`setFolderEncrypted`); a folder whose notes are all encrypted (`folderEncrypted`, read off the files, so it holds on every device) keeps new drafts and notes / folders moved into it encrypted.
- The AI reads encrypted notes only while unlocked and allowed (`settings.aiReadsEncrypted`, Settings → Encryption, on by default; `app.aiReadsEncrypted` / `aiNotes` / `aiActiveId` / `aiBlocksActive`). "Hidden from cloud AI" still applies to them. Text from one marks the chat device-only before it enters (gathered notes, `read_note`); such a chat saved to notes is encrypted, and so is an AI-created note in an encrypted folder. Changes and the conflict view show "Encrypted" instead of a ciphertext diff, and such conflicts are pick-a-side only.

## Renderer state

`lib/stores/app.svelte.ts` is a single `$state` class instance (via `getAppState()`) — workspace, notes/tags, active note, draft state, filters (`selectedTag`/`selectedFolder`), view (`editor`|`settings`), zen, `settings`, and `sidebar` (section visibility + per-path folder/tag expansion). Auto-save is debounced 500ms and flushed on note switch. Settings/theme/sidebar/last-open-file persist to `electron-store` via `window.api.getState`/`setState` (localStorage is kept as a legacy fallback read); `init()` restores them, re-opens the last note, then flips `booted` which fades the UI in. The accent drives full theming: `applyPalette` (accents.ts) sets `--accent` plus accent-tinted `--bg-primary`/`--bg-secondary`/`--text-main` inline on `<html>`, which app.css feeds into every surface — keep its base colors in sync with app.css.

Tabs (`settings.tabs`, Settings → Editor, off by default): `app.tabs` holds note ids (null = the draft), persisted under the `tabs` state key; the open note is the current tab (`tabIndex`). `openNote(id, newTab)` reuses the note's tab, else replaces the current one (Mod+click / middle-click / "Open in new tab": a new one); `createNote` always opens a tab (`placeTab`). A materialized draft's tab takes its id; moves remap, deletes and notes gone from disk drop tabs (not mid-move). `closeTab` opens the neighbour; Mod+W (never the window while on) and Ctrl+Tab. Strip: `NoteTabs.svelte`, in `Editor.svelte` above the header.

Svelte conventions (runes only): classes as clsx-style `class={['a', { on }]}` (no `class:`), `{@attach}` instead of `use:` actions, `style:` directives over interpolated `style="…"`. Global listeners go on `<svelte:window>` (guarded by the open state in always-mounted dialogs); `NoteCard` is the exception — it listens only while its swipe is open, since hundreds of cards on `<svelte:window>` would run on every scroll. Don't set state from an `$effect`: derive it, reset local state with a writable `$derived` (or `$state` inside `$derived.by` for a form that starts over per request, as in `PromptDialog` / `QuestionPanel`), and observe outside sources with `svelte/reactivity` (`MediaQuery`, `innerWidth`, `online`, `createSubscriber`). Effects that remain drive Springs / TipTap or register with the store. Host data that is only ever replaced (notes, tags, folders, changes, stashes, …) is `$state.raw`.

Icons are Lucide (`@lucide/svelte`, one import per icon in `lib/icons.ts`), drawn by `Icon.svelte` (`<Icon name=… />`, menu items name theirs as `icon: '…'`). No hand-drawn SVGs or text glyphs (×, ›, ●) as icons.

Mixed-script fonts (`lib/fonts.ts` `editorStack`): the editor uses one stack — English family first, Arabic family second — so Latin uses the English face and Arabic code points fall back to the Arabic face in LTR _and_ RTL. Don't reorder to Arabic-first (most Arabic faces include Latin glyphs and would capture Latin text).

## Tests

Unit tests are pure logic in Node (`vitest.config.ts` includes `src/**/*.test.ts`), plus git integration tests against temp repos (`gitSync`, `gitChanges`, `isoGit`) and OpenPGP round-trips (`vault/pgp.test.ts`, with `gpg` interop when it's installed; vitest aliases the browser-only `openpgp/lightweight` to `openpgp`). The TipTap plugins and Svelte components are covered by the Playwright suite instead (`e2e/mobile.spec.ts` over `e2e/fakeApi.ts`: phone, tablet portrait/landscape, and mouse-desktop contexts — swipe, sheets, view/edit mode, settings, changes, harness flows). The fake model is scripted by keywords in the message (`multi?`, `md?`, `flaky?`, `long?`, `context?`). Gesture tests must wait for slides/drawers to settle before measuring touch points.
